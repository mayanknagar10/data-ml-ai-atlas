How to Handle a Question You Do Not Know

Represent uncertain reasoning explicitly, detect unsupported conclusions and choose clarifications that separate candidate interpretations.

← Full lessonCombined Python fileREADME

1 · Build it

Minimal implementation with as little framework abstraction as practical.

interpretations={'batch':{'needs':{'data-volume','deadline'}},'online':{'needs':{'qps','latency','consistency'}},'stream':{'needs':{'event-rate','lateness','state'}}}
questions={'execution-mode':{'batch','online','stream'},'latency-target':{'online','stream'},'daily-volume':{'batch','stream'}}
def separation(answered):
    remaining=set(interpretations)
    for q,allowed in answered.items(): remaining&=questions[q] if allowed else remaining-questions[q]
    return remaining
claims=[{'text':'use a queue','kind':'hypothesis','assumptions':{'online'},'checks':{'load-test'}},{'text':'timeout is 30s','kind':'external-fact','assumptions':set(),'checks':set()}]
def unsupported(items): return [c['text'] for c in items if c['kind']!='known' and not c['checks']]

2 · Use it

The same idea through a common library or practical API.

initial=set(interpretations); after_mode=separation({'execution-mode':True}); evidence={'load-test'}; supported=[c for c in claims if c['checks']<=evidence and c['checks']]

3 · Ship it

Log facts, assumptions, hypotheses, checks and confidence separately; verify changing or high-stakes claims with authoritative sources, design safe experiments, and escalate before destructive uncertainty.

4 · Verify it

Assertions and sanity checks that catch conceptual or implementation mistakes.

assert initial=={'batch','online','stream'}
assert after_mode=={'batch','online','stream'}  # an unqualified broad answer does not yet separate them
assert unsupported(claims)==['timeout is 30s']
assert supported[0]['text']=='use a queue'
claims[1]['checks']={'official-docs'}; assert unsupported(claims)==[]
assert questions['execution-mode']==set(interpretations)
